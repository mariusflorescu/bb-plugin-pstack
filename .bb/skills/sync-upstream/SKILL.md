# Sync upstream pstack

You keep this plugin current with upstream pstack without losing its BB adaptations. The deliverable is one open PR against `mariusflorescu/bb-plugin-pstack`, or a one-line "up to date". Never merge.

## Steps

1. **Start clean.** Run every `gh` command as `gh auth switch -u mariusflorescu >/dev/null && gh ...` in the same shell command: the switch does not carry over between commands, and a `GH_TOKEN` taken from `gh auth token` can be stale (it returned 401 while the switched account worked). First check where you are, because the resets below discard local commits: `bb thread show --self --json` must show all of: `.environment.isWorktree` and `.environment.managed` true; `.environment.createdAt` at or after `.thread.createdAt`, so BB created the worktree for this thread (the automation's run and the handoff below both do); and `bb thread list --environment <that environment id> --include-hidden --json` listing only this thread, so no one else works there. Then `git rev-list HEAD --not --remotes` must print nothing, so no commit exists only here. The branch name does not matter (BB's `managedBranchPrefix` setting chooses it). All four hold before any reset. The daily automation creates exactly that. Anywhere else, such as a manual `/sync-upstream` in a regular checkout, do not reset: spawn the sync into its own worktree with `bb thread spawn --project "$BB_PROJECT_ID" --parent-self --new-environment worktree --base-branch origin/main --title "sync-upstream" --prompt "/sync-upstream"`, report its thread, and stop. A thread started by that handoff (titled `sync-upstream`, with a parent) that still fails the check stops and reports the environment instead of spawning again. You run in a fresh BB worktree of this repo, on a branch BB named for this thread, not on `main`. That local name never matters, because step 8 pushes to the sync branch by name. Confirm `git status --porcelain` is empty, then `git fetch origin`. Look for an open PR whose head branch starts `sync/upstream-` with `gh auth switch -u mariusflorescu >/dev/null && gh pr list --repo mariusflorescu/bb-plugin-pstack --state open --json number,headRefName`. If there is one, its head is your sync branch: `git reset --hard origin/<headRefName>` and continue from it, so one PR accumulates until it is merged. Otherwise `git reset --hard origin/main`. Do not `git switch` to either branch. Another checkout may hold it, and git refuses to check a branch out twice.

2. **Run the sync.** `node scripts/sync-upstream.mjs`. The first line of output is the status.
   - `up-to-date`: reply with that line and stop. Do not create a branch or PR.
   - `applied` or `conflicts`: continue. With no open sync PR from step 1, your sync branch is `sync/upstream-<new short sha>`.
   - `error:`: the script wrote nothing and left the pin where it was. Reply with the error line and stop.

3. **Resolve conflicts.** For each file listed under "conflicts to resolve", read the upstream change with `git diff <old sha> <new sha> -- pstack/<upstream path>` (both SHAs are on the status line; `refs/upstream/main` holds the fetched upstream). Keep our BB adaptation and bring in upstream's intent, translated per `BB-NATIVE.md`. The reason after each path says what happened. `edited on both sides` left conflict markers in the file. `deleted here, changed upstream` means this repo removed the file on purpose: keep it deleted and carry upstream's change to wherever that content lives now, if anywhere. `<path> is kept here and is in the way` means upstream turned a file into a directory or back while this repo keeps `<path>`, so upstream's file was not written: settle where our content goes, then add upstream's file. Every other reason left our version in place for you to settle. Leave no conflict markers: `grep -rn '^<<<<<<<\|^>>>>>>>' skills` must print nothing.

4. **Translate what came in.** Read the whole upstream diff for the new range, not only the conflicts. Every Cursor mechanism in the incoming lines becomes its BB mechanism per `BB-NATIVE.md`. Then run `node scripts/check-bb-native.mjs` and fix every finding. If upstream introduced a Cursor mechanism the contract does not cover, add a row to `BB-NATIVE.md` and a rule to `scripts/check-bb-native.mjs` in the same PR, then apply it.

5. **Keep the plugin whole.** Run `node scripts/sync-server-skills.mjs` so `SKILL_NAMES` and `SKILL_SUMMARIES` in `server.ts` match the skill directories and descriptions (the checker flags a mismatch). A new skill whose name collides with a skill in `~/.claude/skills`, `~/.agents/skills` or `~/.bb/skills` gets a `pstack-` alias: add it to `ALIASED` in `scripts/sync-upstream.mjs` and to the aliases table in `MANIFEST.md`. Typecheck with `npm ci --ignore-scripts && npx tsc --noEmit --skipLibCheck`, then run `node --test scripts/`.

6. **Update the manifest.** In `MANIFEST.md`, set the pinned commit to the new SHA and the upstream version to the one in `git show refs/upstream/main:pstack/.cursor-plugin/plugin.json`. `UPSTREAM` was already bumped by the script.

7. **Review, then reconcile, until there are no findings.** First commit the sync itself, signed: `Sync upstream pstack <old short>..<new short>`, with the upstream commit list in the body. The scope is every file this sync changed: `git diff --name-only origin/main` plus new files. Group it by skill directory, at most six directories per group, with `server.ts`, `BB-NATIVE.md` and `scripts/` in their own group. Then loop, starting at round 1:
   - **Review.** The scope's authors are you and the fixers, who run on your `feature, refactoring` model. For each group, spawn one read-only reviewer child per the pstack delegation rules on the first `arena cross-judge pool` entry whose model family differs from both yours and the fixers'. If none does, pick per round against whoever wrote that round's new changes (you in round 1, the fixers after it): the first entry whose family differs from that author's, else the first entry. In that case, name the author family it shares in its scope section and in the PR. Its brief is `references/review-brief.md`, followed by a scope section: `<UPSTREAM_SHA>` is the new pin in `UPSTREAM`, the files in the group, and a "Settled" list of every earlier rejected finding with its evidence. A fresh reviewer every round, never a resumed one. Collect all reports.
   - **Done?** When every report's first line is `NO FINDINGS`, the loop is closed. Go to step 8.
   - **Reconcile.** Fix the reports one at a time. For each report with findings, spawn one fixer child on your `feature, refactoring` model in this environment. Its brief is `references/fix-brief.md` with `<UPSTREAM_SHA>` filled in, then the report. Wait for it with `bb thread wait <id> --timeout 30m && bb thread output <id>` before spawning the next. A fixer that fails goes through the failure steps in the pstack delegation rules first, so a pending provider retry cannot restart it beside the next one. Fixers share this worktree and each runs the repo-wide checker and tests, so two at once would check each other's half-made edits. After the last fixer, read the round's diff yourself, then run `node scripts/check-bb-native.mjs` and `node --test scripts/`. Commit the round, signed: `Reconcile review round <n>`. Add each `rejected` finding and its evidence to the Settled list.
   - **Cap.** Stop after round 5 even with findings open. List them in the PR under "Open review findings" and say so in your reply.

8. **Push and open the PR.** `git push origin HEAD:refs/heads/<sync branch>`. It fast-forwards the open PR's branch, or creates the new one. Write the PR text to `$BB_THREAD_STORAGE/sync-pr.md`: the upstream commits, each conflict and how you resolved it, each Cursor mechanism you translated, each review round with its reviewer's model, the author family it shares if any, its finding count and outcome (fixed or rejected, with evidence), and the checker's summary line.
   - No open sync PR: `gh auth switch -u mariusflorescu >/dev/null && gh pr create --repo mariusflorescu/bb-plugin-pstack --base main --head <sync branch> --title "Sync upstream pstack <old short>..<new short>" --body-file "$BB_THREAD_STORAGE/sync-pr.md"`.
   - Continuing the open PR from step 1: the push already updated it. Comment on it with `gh auth switch -u mariusflorescu >/dev/null && gh pr comment <number> --repo mariusflorescu/bb-plugin-pstack --body-file "$BB_THREAD_STORAGE/sync-pr.md"`.

**Reply:** the status line, the review rounds and whether the loop closed with no findings, the PR link as `https://github.com/mariusflorescu/bb-plugin-pstack/pull/<number>`, and anything you could not translate with confidence.
