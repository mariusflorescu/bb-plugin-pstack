### Pause safely

**You own a clean stop. Leave a checkpoint a cold-start agent can resume from.** This is explicit only. On "keep going", "going to bed, keep going", or "don't stop", do not pause.

1. Stop at a safe boundary. Finish the current atomic step or back out of it. Start nothing new, and cancel any nested subagents with `scripts/pause-tree.sh "$BB_THREAD_ID"` from this skill's directory. It pauses every automation that would re-prompt this thread or a descendant, in each project a thread of the tree lives in, discards the queued messages this program created on this thread and its descendants (tells sent from this tree, due notices of automations this tree created), then stops every descendant thread at any depth, hidden ones included, until one pass finds them all settled. A machine can still run a turn for a thread BB lists as idle or error, and only an explicit stop interrupts it, so the script stops each descendant at least once whatever its listed status, and counts it settled only after that stop succeeded and a later pass lists it idle or error. It never stops this thread. `bb thread stop` leaves a queue intact, so any other queued message (the user's, a retry, another program's) would restart its thread later. The script leaves those queued and never stops their threads. Never delete one yourself. Before each delete, it saves the message to `$BB_THREAD_STORAGE/pause-tree-<thread-id>.jsonl` as one JSON row per message `id` with the target `threadId`, the `senderThreadId` and the `content`, then reads it back. If that save fails, it stops there with `error: cannot save queued message`, discards nothing more and leaves the tree unsettled, so fix the storage and rerun it. Every run of the script adds to that one file. Right after the last run for this pause, move it to `$BB_THREAD_STORAGE/pause-<time>.jsonl`, where `<time>` comes from `date -u +%Y%m%dT%H%M%SZ`. When the runs discarded nothing, the file does not exist, so create `pause-<time>.jsonl` empty instead. An empty file means this pause has nothing to replay. A later pause then starts a fresh file, and each resume replays only its own pause. A non-zero exit names the threads still running and every message left queued on them. A message on this thread from outside the program stays queued too and is named, but does not fail the run, since it wakes only this thread. Do not checkpoint while a named thread is running, and name each message left queued, this thread's included, to the operator.
2. Take no irreversible action to pause. No PR and no push unless you already had one out.
3. Make the work durable. Commit uncommitted edits as one clear `wip:` commit on the current branch so nothing is lost. If the tree is broken, say so in the commit body in one line.
4. Write the resume note off-context. Capture intent, what you were doing, progress and what's verified, current state, next steps, key files, gotchas, the automations the script paused with the project it prints for each (`paused automation <id> in <project>`), the absolute path of this pause's `pause-<time>.jsonl`, and that the resume follows step 5 before anything else. For the compaction trigger write it to a file like `$BB_THREAD_STORAGE/<slug>-resume.md`. If a show-me-your-work trail exists, point at it instead of duplicating it.
5. On resume, recover before you replay. A replayed message or a resumed automation starts a turn on the thread it reaches, and a tell to a thread the script stopped restarts it mid-step. So recover each child of the paused thread before anything wakes it or a thread under it. That covers every child that a row of `pause-<time>.jsonl` is aimed at, or that sits above the row's thread (follow `.thread.parentThreadId` in `bb thread show <id> --json` up to a child of the paused thread), and every other stopped child you mean to wake. Each resume attempt takes one attempt id, `pause-<time>-r<now>`, where `<now>` comes from `date -u +%Y%m%dT%H%M%SZ` when the attempt starts, so no two attempts share one. Send each of those children its recovery message with `bb thread tell <child-thread-id> --message-file <path> --json`. The message carries the attempt id and says the child's last turn was cut mid-step and its subagents were stopped. The child re-reads its branch, worktree and child threads, replies `RECOVERED <attempt id> <head SHA>` with what it found, and writes nothing until your go. A `queued` delivery waits on that child's open interaction. Do not resend it. Name the interaction to the operator. Collect each reply in the background by repeating `bb thread wait <child-thread-id>` then `bb thread output <child-thread-id>`, a few seconds apart, until the output starts with `RECOVERED <attempt id> `. Only that output is the acknowledgement. `bb thread wait` returns at once on a thread still idle before the request starts, and `bb thread output` is the thread's latest reply, whichever request produced it, so an output without this attempt id is an earlier recovery's or another turn's. A queued recovery stays pending until its row has run and the reply carries the id. Only after a child's acknowledgement, send it its go with `bb thread tell`. The go quotes each row aimed at that child or at a thread under it, with the row's `threadId` and `senderThreadId`. The child acts on each row that is still current, and resends or replaces each subagent's work. Read the rows aimed at the paused thread yourself. As soon as the tell carrying a row succeeds, or you have read the row, append its `id` to `pause-<time>.sent` beside the `.jsonl`. Skip every `id` already there, so a retried resume never resends one. Resume each paused automation with `bb automation resume <id> --project <project>` only after every child you woke has acknowledged and taken its go.

**Reply:** where you are in the loop, what's on disk versus still in your head (paths, no diff dumps), the commits you made and whether the tree is clean, and the first action on resume. This is a pause, not a final report.
