### Worktree and simulator cleanup

**You own the disk and the safety gate.** Prune merged or abandoned git worktrees and stale iOS simulators to reclaim space. Deletion is irreversible, so every step guards against deleting something in use or holding uncommitted work.

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh` (principle-build-the-lever). It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that BB or another tool created elsewhere (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the BB environment on it (`ENV`), with its newest thread activity and whether any thread there, or any ancestor of one, is pinned or running (`LAST_THREAD`). Then it suggests a bucket. `du` over large worktrees is slow and rows print only once every worktree is measured, so background it.
2. The bucket is advice, not permission. BB's live thread state is the real artifact (principle-prove-it-works). The script holds a worktree whose threads or their ancestors are pinned or running (`hold-in-use`). It sees only threads whose environment is that worktree, and it warns and holds nothing when `bb` is unavailable. Re-read each candidate's threads with `bb thread list --environment <ENV>` right before deleting, since pins and runs change.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, read `bb thread output <id>` for each thread on it and decide whether its work is finished. Fan subagents out to read `bb thread log <id>` when the logs are long (principle-guard-the-context-window, logs are bulk). A row with no `ENV` can still be in use by a thread that works in it by path from another environment. Run `bb thread search <worktree dir name>` and check the hits from this project.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway, safe to drop, but name the files. Per Autonomy, clean and merged and not-in-use proceeds. `wip` and in-use pause.
5. Prune the confirmed set. A row with an `ENV` is a BB environment, so release it through BB, not git. `bb environment archive-threads <ENV>` archives its threads, and BB tears a managed worktree down five minutes later and keeps the branch. `bb environment delete <ENV>` requests the same cleanup when no thread is live. Confirm with `bb environment show <ENV>` that it reaches destroyed. For a row with no `ENV`, or a worktree BB left in place, run `git worktree remove --force <path>`. If the dir survives on ignored build artifacts, `rm -rf` it, then `git worktree prune`. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in use by which thread, or uncommitted work).
