### Worktree and simulator cleanup

**You own the disk and the safety gate.** Prune merged or abandoned git worktrees and stale iOS simulators to reclaim space. Deletion is irreversible, so every step guards against deleting something in use or holding uncommitted work.

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh` (principle-build-the-lever). It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that BB or another tool created elsewhere (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, work removal would lose (`DIRTY`), PR state, and BB usage. `SNAPSHOT` hashes that work, HEAD plus every index entry plus the tracked diff plus every untracked file's path and content, because the `DIRTY` counts stay the same when one file is swapped for another and staged content can change while the working tree does not. It adds the same for each checked-out submodule at any depth, plus the submodule's local refs, because git's diff names a submodule by one commit and a linked worktree keeps its submodules' repositories in its own git dir, so removal deletes them. `ENV` lists the BB environments on this machine at its path or at a directory inside it, since a thread can attach to any directory. `MENTIONS` lists the threads in this repo's BB projects whose logs name the path. `LAST_THREAD` is their newest activity, to the millisecond (UTC), and whether any of them, or an ancestor, is pinned or running. `CASCADE` lists the other environments that archiving its threads would reach. Then it suggests a bucket. `du` over large worktrees and the log scan are slow, and rows print only once every worktree is measured, so background it.
2. The bucket is advice, not permission. BB's live thread state is the real artifact (principle-prove-it-works). The script holds a worktree in use (`hold-in-use`), one whose archive would cascade into another environment (`hold-cascade`), and every row when it cannot read BB or a row whose work it cannot read, such as a broken submodule (`hold-unknown`). These outrank `hold-wip`, so a user can release uncommitted work only on a row no thread holds. Rerun it once BB answers. Pins, runs and children change, so step 5 rechecks right before deleting.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, read `bb thread output <id>` for each thread on it and decide whether its work is finished. Those are the threads in `bb thread list --environment <ENV> --include-hidden` plus the ones in `MENTIONS`. Fan subagents out to read `bb thread log <id> --format verbose --all` when the logs are long (principle-guard-the-context-window, logs are bulk). The mention scan covers only this repo's projects. Do not list or search threads across projects to widen it. That reads private chats from unrelated projects.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. `untracked:N` is N files git neither tracks nor ignores. Treat them as new source until the user says otherwise. Build output git ignores does not count. `unreachable` is a detached HEAD whose commits no branch, tag or remote ref holds, or a submodule commit none of that submodule's remote-tracking refs holds. A submodule's edits count once, as its gitlink, and the superproject's diff shows only `-dirty`, so show `git -C <submodule> status` and `diff HEAD` too. Show the diff, the file names or the commits and get a decision first, since removing a clean worktree is recoverable from its branch but this work is gone. Record the row's `SNAPSHOT` with the decision. The user released that snapshot and nothing else. Per Autonomy, clean and merged and not-in-use proceeds. Every `hold-*` row pauses.
5. Prune the confirmed set. Right before deleting, rerun `scripts/worktree-audit.sh <repo> <path>...` on just the confirmed paths. Prune a row only when the fresh run still says `safe`, or still shows exactly what the user released (the same `SNAPSHOT` for `hold-wip`, the same `PR` for `hold-open-pr`, no newer `LAST_THREAD` for `verify-recent-chat` or `review`). Never prune a `hold-in-use`, `hold-cascade` or `hold-unknown` row. Its state has to change first (unpinned, stopped, the cascaded environments pruned first, BB reachable). A row with an `ENV` holds BB environments, so release each through BB before git. `bb environment archive-threads <ENV>` archives its threads and everything BB's archive cascade reaches from them, which is why `CASCADE` must be `-`. BB tears a managed worktree down five minutes later and keeps the branch. Unarchiving a thread inside those five minutes cancels the teardown. `bb environment delete <ENV>` requests the same cleanup when no thread is live. Confirm with `bb environment show <ENV>` that it reaches destroyed. For a row with no `ENV`, or a worktree BB left in place, run `git worktree remove <path>`. Without `--force`, git refuses a worktree that gained modified or untracked files since the recheck. A changed `SNAPSHOT` is new work, so show it and ask again. Add `--force` only for a row whose released `SNAPSHOT` the recheck just matched, or a clean row the recheck just passed that git refuses only with `working trees containing submodules cannot be moved or removed`, which git says of any worktree with a checked-out submodule, clean or not. If the dir survives on ignored build artifacts, `rm -rf` it, then `git worktree prune`. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in use by which thread, which environments its archive would reach, uncommitted work, or BB unreadable).
